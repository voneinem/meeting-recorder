# Tasks: Offline Transcription (Phase 2)

**Input**: Design documents from `/specs/002-offline-transcription/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/, quickstart.md

**Tests**: Constitution Principle VII requires format and pipeline logic in `:core` to be fully unit-tested, so `:core` test tasks are included and come before their implementation. The engine, the worker and the UI are verified by the instrumented tests of plan.md and by the manual scenarios S11 to S24 in [quickstart.md](quickstart.md).

**Organization**: Tasks are grouped by user story. Story phases follow the delivery order of research R-19 (the P1 stories first, then the list status, the transcript view, the resilience story and re-transcription), which is not the numeric order of the spec. The spike is the first work item (Phase 1) and gates the model catalog. Every checkpoint leaves an installable, usable app (Principle VIII).

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependency on an incomplete task)
- **[Story]**: US1 to US6, as numbered in spec.md
- Paths follow plan.md. `PKG` means `app/meetingrecorder`, so `core/src/main/kotlin/PKG/core/` is `core/src/main/kotlin/app/meetingrecorder/core/`, `app/src/main/kotlin/PKG/` is `app/src/main/kotlin/app/meetingrecorder/` and `whisper/src/main/kotlin/PKG/whisper/` is `whisper/src/main/kotlin/app/meetingrecorder/whisper/`.
- **(device)** marks a task that needs the real phone (Gigaset E940, Android 14) and **(user)** one that needs the project owner (unlock the phone, supply a recording, take a decision). Do not tick a device task before its scenario passed on the phone; write the date and any deviation next to it.
- **Language rule (Principle IX)**: code, comments, commit messages and generated files are English. Every task that adds a user-facing string adds it to **both** `app/src/main/res/values/strings.xml` (English) and `app/src/main/res/values-de/strings.xml` (German) in the same change.
- Use `export JAVA_HOME=~/Android/jdk-21 ANDROID_HOME=~/Android/Sdk` for every Gradle call. Commit only when the project owner asks.

## Implementation Strategy

### MVP First (User Stories 1 and 2)

1. Phase 1: toolchain, submodule, spike, decision gate (the spike can falsify SC-003 before any UI exists).
2. Phase 2 Foundational: engine module and gates, tested pure core, storage base.
3. Phase 3 User Story 1, then Phase 4 User Story 2.
4. **STOP and VALIDATE**: quickstart S11 to S14 on the phone, plus the automated gate (`:core:test`, lint, the new build checks).
5. Install it: models can be installed and a meeting transcribed into its folder, offline.

### Incremental Delivery

1. Spike and foundation: the engine builds, loads and decodes on the phone; the format and pipeline logic is tested.
2. US1: models (usable on its own, harmless without the rest).
3. US2: transcription in the background (the P1 MVP).
4. US5: status in the list.
5. US3: the transcript view with tap-to-seek and photos.
6. US4: cancel, crash safety, resume, recording priority (do this before sharing the app widely: it is the trust story).
7. US6: re-transcription.
8. Polish: German review, docs, F-Droid notes, reproducibility, long meeting, network audit, regression.

### Notes

- The spike gates only the model catalog; if it shows that no multilingual candidate reaches real time, stop at `T017` and decide with the project owner before building more on SC-003.
- Any task that adds or upgrades a dependency or plugin re-runs `./gradlew --write-verification-metadata sha256` and commits `gradle/verification-metadata.xml` for review; the submodule is only ever bumped together with `gradle/whisper.pin`.
- Never run `connectedDebugAndroidTest` on the phone with real data (Gradle uninstalls the app and wipes the storage grant); use `adb shell am instrument` as in Phase 1.
- Never write recordings, transcripts or spike results with real meeting content into the repository (`spike/audio/`, `spike/models/` and `spike/out/` are ignored).
- Commit only when the project owner asks, in English, after a task or logical group.
- Never mark a story done before its quickstart scenario passes on the phone.
