# Contract: Meeting Folder (schemaVersion 1)

This is the public, documented file format of Meeting Recorder (Constitution Principle IV). The
folder is the single source of truth; any tool, including Claude Code, must be able to read it
without the app.

## Layout

```text
<storage folder>/
└── 2026-11-15_14-30-00/        # one folder per meeting, named after the local start time
    ├── meeting.json            # metadata, see meeting.schema.json
    ├── CLAUDE.md               # generated English guide for people and AI assistants
    ├── audio.wav               # the whole meeting audio, one continuous file
    └── photos/
        ├── photo-001.jpg
        └── photo-002.jpg
```

## Rules

1. **Folder name**: `YYYY-MM-DD_HH-mm-ss` in the device's local time at recording start. On
   collision `-2`, `-3`, ... is appended. The name is stable: renaming a meeting changes only
   `title` in `meeting.json`.
2. **`audio.wav`**: RIFF/WAVE, PCM (format tag 1), 16-bit little-endian, sample rate from
   `audio.sampleRate` (48000 in Phase 1), 1 or 2 channels, canonical 44-byte header. Channel
   layout is constant for the file. In stereo meetings recorded with a two-speaker source, the left
   channel is speaker A and the right channel speaker B, until a `sourceSwitches` entry with
   `channelsDuplicated: true` says otherwise.
3. **Timeline**: Every position in the folder is a sample-frame index into `audio.wav` (`atFrame`),
   counted from the first frame of the file. `atMs` is a convenience value derived from `atFrame`.
   Paused time and the short gap during a microphone switch are not part of the timeline.
   Wall-clock values (`startedAt`) are informational only.
4. **Photos**: JPEG files in `photos/`, named `photo-NNN.jpg` with a 3-digit running number. Each
   photo is listed in `meeting.json` with its `atFrame`.
5. **`meeting.json`**: UTF-8 JSON, validated by [meeting.schema.json](meeting.schema.json). Readers
   MUST ignore unknown fields and MUST refuse unknown `schemaVersion` major values.
6. **`CLAUDE.md`**: Markdown in English, generated by the app, describing this folder (layout,
   formats, timeline rules, how to read `meeting.json`) and suggested follow-up tasks (summary,
   minutes, action items, using photo positions as context). It may be regenerated by the app; user
   notes belong in separate files.
7. **Status**: `status` is `recording` while the meeting is being recorded (or after a crash and
   before recovery), `complete` after a normal stop, `recovered` after the app repaired an
   interrupted meeting.
8. **Unknown files**: Additional files and folders (for example transcripts added in later phases
   or by the user) MUST be preserved by the app and ignored when listing.

## Compatibility

- A change that adds optional fields keeps `schemaVersion`. A change that renames, removes or
  re-types a field increments `schemaVersion` and ships a migration (Constitution IV).
- The app lists any directory in the storage folder that contains a `meeting.json` or an
  `audio.wav`; invalid ones are shown with what can be determined.

## Generated `CLAUDE.md` content (outline)

The generator in `:core` MUST produce, in English and with the actual values of the meeting
substituted:

1. Title and one-line description of the meeting (title, start, duration, channel layout).
2. "Folder contents": the table of files above, with the real photo count.
3. "How to read the timeline": frame/millisecond rules from rule 3, sample rate of this meeting.
4. "Channels": what the left and right channel mean for this meeting and any switch positions.
5. "Photos": list with file name and position as `mm:ss`.
6. "Suggested follow-up tasks": summary, minutes, action items, decisions; each with a short prompt
   suitable for Claude Code, noting that transcription is not yet part of the folder.
7. "Format reference": pointer to the fields in `meeting.json`.
